# FAJR — Self-Repair Protocol

هذا الملف يُستخدم في كل مراجعة للمشروع. لا تعتبر وجود الكود دليلًا على أن الميزة تعمل.

## دورة الإصلاح
1. افحص شجرة المستودع والتغييرات الحالية قبل التعديل.
2. شغّل `flutter pub get` و`dart format --output=none --set-exit-if-changed .` و`flutter analyze` و`flutter test` عندما تكون Flutter متاحة.
3. افحص Workflow البناء وتأكد من إنشاء Android platform files عند غيابها.
4. أصلح السبب الجذري بدل تعطيل الاختبار أو حذف الميزة.
5. أعد تشغيل الاختبار المتأثر والاختبارات المرتبطة.
6. سجّل الدليل الفعلي على نجاح الإصلاح في `docs/KNOWN_ISSUES.md`.
7. لا تضع الحالة Verified إلا بعد تشغيل اختبار مناسب بنجاح.
8. إذا احتاج الاختبار Firebase أو مزود مكالمات أو جهازًا فعليًا، سجّل الحالة Blocked/Needs device test ولا تدّعِ نجاحه.

## أولويات الخطورة
- **P0:** تسريب أسرار، تجاوز صلاحيات، فقدان بيانات.
- **P1:** فشل البناء، تعطل بدء التشغيل، وصول غير مصرح، خلل أساسي في المكالمات أو النقاط.
- **P2:** ميزة رئيسية غير مكتملة، مزامنة خاطئة، خلل RTL أو التوقيت.
- **P3:** تحسينات بصرية أو توثيقية غير مانعة للاستخدام.

## قائمة تحقق
- [ ] ملفات Flutter ومسارات الاستيراد صحيحة.
- [ ] الاعتمادات قابلة للحل.
- [ ] التنسيق والتحليل والاختبارات نجحت فعلًا.
- [ ] Workflow YAML صالح وكل الخطوات داخل `jobs.<job>.steps`.
- [ ] Workflow البناء يولّد Android platform files عند غيابها.
- [ ] APK المرفوع موجود فعلًا وهو الناتج المتوقع.
- [ ] لا توجد أسرار في المستودع أو سجلات CI.
- [ ] الأزرار لا تدّعي نجاح وظائف غير منفذة.
- [ ] الوضع المحلي لا يزعم أن Firebase أو المكالمات تعمل.
- [ ] نصوص القرآن والأذكار كاملة وموثقة قبل إعلان اكتمال المحتوى.
- [ ] مواقيت الصلاة لا تُعرض دون مدينة وإعدادات حساب واضحة.
- [ ] كل ميزة غير مكتملة موثقة.

## المكالمات والحسابات — عند تنفيذها
- تحقق من موافقة الطرف المستقبِل وإعداداته.
- إصدار رموز المكالمات المؤقتة من الخادم فقط.
- احتساب النقاط على الخادم ومنع تكرار الأحداث.
- اختبر القبول والرفض والانقطاع والشاشة المقفلة على جهازين فعليين.
- لا تضع مفاتيح Firebase الخاصة أو مفاتيح مزود المكالمات في الكود.
